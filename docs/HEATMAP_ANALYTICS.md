# LILA BLACK — Spatial Heatmaps & Telemetry Analytics (Phase 6)

## 1. Executive Summary

Phase 6 implements a spatial analytics and thermal intelligence system for **LILA BLACK — Player Intelligence**. The engine directly consumes the pre-computed 2D spatial matrices generated by the Python ETL pipeline (`data/processed/maps/<map_name>/heatmaps.json`) and renders high-performance offscreen rasters directly over the existing interactive minimap Canvas.

Analysts can dynamically toggle 6 discrete activity layers, inspect raw event counts in any $64 \times 64$ sector, adjust opacity, switch between thermal and grid visualization modes, and review map-wide hotspot rankings.

## 3. Coordinate System & Grid Calibration

### 3.1 Mathematical Alignment
The grid matrix is $64 \times 64$ ($4,096$ sectors).
- **Col Index $c \in [0, 63]$**: Maps West $\to$ East ($u \in [0.0, 1.0]$).
- **Row Index $r \in [0, 63]$**: Maps North $\to$ South ($v \in [1.0, 0.0]$).

Given screen pixel coordinates $(p_x, p_y)$ on a minimap of dimensions $(\text{width}, \text{height})$:
$$\text{col} = \min\left(63, \max\left(0, \left\lfloor \frac{p_x}{\text{width}} \times 64 \right\rfloor\right)\right)$$
$$\text{row} = \min\left(63, \max\left(0, \left\lfloor \frac{p_y}{\text{height}} \times 64 \right\rfloor\right)\right)$$

Inverse transformation to in-game 3D world bounding box $([x_{\min}, x_{\max}], [z_{\min}, z_{\max}])$:
$$\begin{aligned}
u_{\min} &= \frac{c}{64}, \quad u_{\max} = \frac{c + 1}{64} \\
v_{\min} &= 1.0 - \frac{r + 1}{64}, \quad v_{\max} = 1.0 - \frac{r}{64} \\
x_{\min} &= O_x + u_{\min} \times S, \quad x_{\max} = O_x + u_{\max} \times S \\
z_{\min} &= O_z + v_{\min} \times S, \quad z_{\max} = O_z + v_{\max} \times S
\end{aligned}$$

This preserves exact spatial alignment with terrain roads, bridges, and compound buildings across all 3 maps, including Grand Rift's native non-square raster ($2048 \times 2046$).

## 4. Normalization and Raw Count Semantics

### 4.1 Strict Raw Count Integrity
Underlying integer counts in `heatmaps.json` are **never modified, rounded, or approximated**. Tooltips, sector detail cards, and the Spatial Analytics modal always present exact integer counts.

### 4.2 Visualization Normalization Modes
To accommodate vast volume discrepancies between layers (e.g. Ambrose Valley `human_traffic` with max 476 vs `killed_by_storm` with max 1):
1. **Relative Normalization (Default)**:
   $$\text{intensity} = \sqrt{\frac{\text{count}}{\text{layer.max\_cell\_count}}}$$
   Square-root scaling enhances visibility of low-frequency events and faint movement corridors without blowing out peak clusters.
2. **Absolute Normalization**:
   $$\text{intensity} = \sqrt{\frac{\text{count}}{\max_{l \in \text{active}}(\text{layer}_l\text{.max\_cell\_count})}}$$
   Normalizes across all currently enabled layers, showing absolute volumetric dominance.

## 5. Rendering Engine & Performance

- **Zero-Lag Offscreen Rasterization**: An offscreen `HTMLCanvasElement` ($64 \times 64$ pixels) is generated using raw `ImageData` and cached in a LRU raster cache by `(map_id, active_layers, opacity, style, norm_mode)`.
- **GPU Hardware Draw Quad**: During active zoom, pan, and 60 FPS timeline playback, the main Canvas executes a single `ctx.drawImage(offscreenRaster, 0, 0, width, height)`. This takes $< 0.05\text{ ms}$, creating zero CPU overhead and preventing animation frame drops.
- **Render Styles**:
  - `Thermal Smooth`: Uses bilinear canvas interpolation (`imageSmoothingEnabled = true`) for smooth organic gradient blending.
  - `Crisp Grid`: Uses nearest-neighbor sampling for discrete, sharp $64 \times 64$ sector boundaries.

## 6. Supported Filters and Granularity Constraints

| Filter Parameter | Granularity Supported | Behavioral Scope |
|---|---|---|
| **Map Selection** | ✅ **Map-Specific** | Dynamically switches to active map's $64 \times 64$ heatmap matrix. |
| **Active Layers** | ✅ **6 Independent Layers** | Toggle any combination of Human, Bot, Loot, BotKill, BotKilled, StormDeaths. |
| **Render Style & Opacity** | ✅ **Interactive Controls** | Real-time slider from 10% to 100%; thermal vs grid toggle. |
| **Date & Match Filters** | ⚠️ **Aggregate Dataset Scope** | `heatmaps.json` provides map-wide aggregate distributions across all 5 days. Date and match filters filter trajectory paths and replay scrubbing, while heatmap overlay displays the baseline density. |
| **Timeline Playback** | ⚠️ **Aggregate Dataset Scope** | Historical temporal playback advances player head markers and events; heatmap remains as background territorial context. |

> [!NOTE]
> As required by data integrity guidelines, we do not fabricate non-existent temporal partitions or fake match-level heatmaps. The UI explicitly communicates the aggregate scope via an informational disclaimer.

## 7. Known Limitations

1. **Spatial Aggregation**: Because the ETL pipeline computes grid counts across the full 5-day dataset, temporal evolution of heatmaps over the course of a match requires sub-second grid partitioning in the ETL pipeline.
2. **Fixed Grid Resolution**: Spatial resolution is fixed at $64 \times 64$ sectors (~$14.06\text{ m} \times 14.06\text{ m}$ per cell on Ambrose Valley). Micro-scale indoor movement inside small sheds cannot be separated from compound courtyards.
3. **No Killer-Victim Relationships**: Telemetry logs record `BotKill` and `BotKilled` as distinct event rows; combat heatmaps display event density locations, not engagement line vectors between two players.
